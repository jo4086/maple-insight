# Maple Insight

메이플스토리 캐릭터 데이터를 조회하고, 성장/스탯/장비 관련 분석과 시뮬레이션을 제공하기 위해 만들던 웹 서비스 프로젝트입니다.

혼자서 프론트엔드, 백엔드, 데이터 수집, 공통 타입, 계산 로직까지 설계해보며 실제 서비스가 어떤 구조로 나뉘는지 학습하기 위해 시작했습니다. 현재는 모든 기능을 완성하기보다, 프로젝트를 통해 배운 설계 과정과 구현 경험을 정리하는 단계입니다.

## 프로젝트 목적

게임 데이터는 캐릭터, 장비, 스탯, 직업, 랭킹, 유니온 등 다뤄야 할 정보가 많고 서로 연결되어 있습니다.

이 프로젝트에서는 단순히 API 데이터를 화면에 보여주는 것을 넘어, 다음과 같은 문제를 직접 다뤄보고자 했습니다.

- 외부 API 응답을 어떻게 정리해서 서비스에서 사용할지
- 프론트엔드와 백엔드가 같은 데이터 기준을 공유하려면 어떻게 해야 하는지
- 복잡한 게임 계산 로직을 어디에 분리해야 유지보수하기 쉬운지
- 데이터 수집, API 서버, 사용자 화면을 어떤 구조로 나눌 수 있는지

## 주요 구현 내용

- Nexon Open API 응답 타입 분리
- 캐릭터, 랭킹, 유니온 관련 API 타입 패키지 구성
- 프론트엔드와 백엔드가 공유할 계약 타입 설계
- Express 기반 백엔드 API 구조 작성
- React 기반 프론트엔드 화면 구조 작성
- 캐릭터 정보 조회 및 장비/스탯 데이터 처리 시도
- 게임 데이터 수집용 ingestor 구조 작성
- 스탯/심볼 계산 로직 패키지 작성
- 계산 로직에 대한 Vitest 테스트 작성
- 모노레포 기반 앱/패키지 분리

## 프로젝트 구조

```txt
apps/
  frontend/   사용자 화면
  back/       API 서버
  ingestor/   외부 데이터 수집 작업
  erd/        ERD 관련 실험용 앱

packages/
  api-types/  Nexon API 원본 응답 타입
  contracts/  프론트엔드와 백엔드가 공유하는 타입
  game-data/  게임 정적 데이터
  simulator/  스탯/심볼 등 계산 로직
  database/   DB 관련 패키지
  generator/  데이터 생성/가공 스크립트
```

## 설계 방향

이 프로젝트에서 가장 중요하게 생각한 부분은 역할 분리였습니다.

처음에는 API 데이터를 받아와 바로 화면에 보여주는 방식으로 생각했지만, 게임 데이터는 종류가 많고 계산 규칙도 복잡했습니다. 그래서 데이터를 다음과 같이 분리해서 다루는 방향으로 구조를 잡았습니다.

- `api-types`: 외부 API 응답을 최대한 원본에 가깝게 표현
- `contracts`: 서비스 내부에서 안정적으로 사용할 타입 정의
- `game-data`: 직업, 장비, 스탯 등 게임 규칙에 가까운 데이터 관리
- `simulator`: 계산이 필요한 로직을 별도 패키지로 분리
- `apps`: 실제 실행되는 프론트엔드, 백엔드, 데이터 수집기 배치

## 배운 점

### 1. 큰 프로젝트는 코드보다 구조가 먼저 중요하다

처음에는 기능을 빠르게 만들고 싶었지만, 다뤄야 할 데이터가 많아질수록 폴더 구조와 데이터 흐름을 먼저 정리하는 것이 중요하다는 것을 느꼈습니다.

### 2. 프론트엔드 화면을 생각하면 필요한 데이터가 명확해진다

백엔드부터 모든 데이터를 만들려고 하면 범위가 너무 커졌습니다. 반대로 사용자가 볼 화면을 먼저 생각하니 어떤 데이터가 필요한지, 어떤 데이터는 당장 필요하지 않은지 판단하기 쉬웠습니다.

### 3. 타입을 공유하면 실수를 줄일 수 있다

프론트엔드와 백엔드가 같은 데이터를 서로 다른 이름이나 구조로 다루면 실수가 생기기 쉽습니다. TypeScript 타입을 공통 패키지로 분리하면서 데이터 구조를 맞추는 경험을 했습니다.

### 4. 혼자서 모든 영역을 완성하는 것은 어렵다

이 프로젝트는 프론트엔드, 백엔드, 데이터 수집, DB, 계산 로직까지 범위가 넓었습니다. 혼자 모든 기능을 완성하기에는 부담이 컸고, 그래서 현재는 완성된 서비스보다 학습 과정과 설계 경험을 보여주는 프로젝트로 정리하고 있습니다.

## 현재 상태

이 프로젝트는 개발을 일시 중단한 상태입니다.

완성된 상용 서비스는 아니지만, 복잡한 도메인을 분석하고 프로젝트 구조를 나누며 TypeScript 기반 서비스 구조를 연습한 기록입니다. 이후에는 범위를 줄여 핵심 기능만 다시 구현하거나, 이 경험을 바탕으로 더 작은 프로젝트를 완성하는 방향을 고려하고 있습니다.
