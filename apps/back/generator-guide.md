## 생성 지침서

**필수사항**:
`evaluator`와 스프린터 계약을 수행.

**example**:

    이번에 만들건 무엇인지: [기능명]
    완료 기준: [체크리스트]
    기능명.md의 최상단에 기록

- 한번에 하나의 기능만을 만들 것.

- 피드백이 들어오면 적극 수용하고 수정할 것.

- 기능 문서 기록방법:
  - 설계의 이유를 논리적으로 설명할 것.
  - 피드백이 들어온것에 대해 수정하고나면 왜 그렇게 수정했는지 자세히 설명할 것.
  - 코드를 생성하거나 수정사항을 반영했을때 계속해서 타이틀을 넣어서 구분할 것
  - 서브 타이틀 규칙:
    - ### {number}. 생성한 코드
    - ### {number}-{number}. 생성한 코드의 수정사항을 반영했을때
