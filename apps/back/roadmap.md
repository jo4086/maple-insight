## 프로젝트 방향

이 프로젝트는 단순한 웹앱이 아니라, 메이플 데이터를 수집하고 해석하며 시뮬레이션까지 확장할 수 있는 작은 플랫폼을 목표로 한다.

현재 구상에 포함된 축은 다음과 같다.

- 프론트 UI/UX
- 반응형 디자인
- 백엔드 API 수집 및 정규화
- 게임 데이터 모델링
- 시뮬레이터 엔진
- 사용자 데이터 저장
- AI 보조 인터페이스
- 자연어 기반 시뮬레이션 오케스트레이션

이 규모에서는 기능 추가보다 먼저 경계를 설계하는 것이 중요하다.  
레이어를 분리하지 않으면 데이터 수집, 게임 로직, 저장, UI, AI가 한 덩어리로 엉키게 된다.

## 핵심 레이어

### 1. 데이터 수집 레이어

역할:
- 외부 API fetch
- raw 타입 정의
- normalized 타입 정의
- mapper
- 캐시

산출물:
- 프론트와 시뮬레이터가 사용할 수 있는 정규화된 도메인 데이터

### 2. 도메인 모델 레이어

역할:
- 메이플의 직업, 스탯, 장비, 강화, 심볼, 세트효과 등 게임 구조를 코드로 표현

산출물:
- 시뮬레이터와 애플리케이션이 공통으로 사용하는 게임 규칙 모델

### 3. 시뮬레이션 레이어

역할:
- 계산기
- 강화/교체/세팅 비교
- 특정 전략 검증

산출물:
- 입력 조건에 따라 재현 가능한 계산 결과와 비교 결과

### 4. 애플리케이션 레이어

역할:
- 유저 데이터 저장
- 빌드/세팅 저장
- 이력 관리
- 비교 결과 저장

산출물:
- 유저 단위의 상태와 기록

### 5. AI 오케스트레이션 레이어

역할:
- 자연어 입력 해석
- 어떤 시뮬레이터를 호출할지 결정
- 필요한 입력 보완
- 결과를 설명형으로 반환

산출물:
- 유저 요청을 구조화된 시뮬레이션 작업으로 변환한 실행 흐름

### 6. 프론트 표현 레이어

역할:
- 검색
- 캐릭터 보기
- 비교
- 시뮬레이터 UI
- AI 대화형 인터페이스

산출물:
- 사용자가 흐름을 쉽게 이해하고 조작할 수 있는 인터페이스

## AI에 대한 원칙

AI는 마지막에 붙여야 한다.  
초기에 AI를 먼저 붙이는 것이 아니라, 아래 기반이 먼저 준비되어야 한다.

- 정규화된 데이터 모델
- 신뢰 가능한 시뮬레이션 함수
- 저장 가능한 유저 상태
- 명시적인 입력 스키마

AI의 역할은 직접 계산하는 것이 아니라:

- 사용자의 말을 구조화된 요청으로 바꾸고
- 적절한 시뮬레이터를 호출하고
- 결과를 요약하고 설명하는 것

으로 한정해야 한다.

## 현재 우선순위

미래 그림을 실현하기 위한 현재 우선순위는 다음과 같다.

1. `character` 도메인 정규화 완료
2. 공통 타입 패키지 안정화
3. 프론트에서 normalized 데이터 기반 UI 완성
4. 핵심 시뮬레이터 1개 먼저 구현
5. 유저 저장용 DB 모델 설계
6. AI 연결

## 현재 단계에서 하지 않을 것

아래 항목은 방향성에는 포함되지만 현재 최우선 구현 대상은 아니다.

- AI 직접 연결
- 다수의 시뮬레이터를 동시에 구현
- 복잡한 추천 시스템
- DB 중심의 기능 확장

현재는 데이터 정규화, 타입 안정화, 프론트 렌더링 기반 확보가 우선이다.
