# 버전 비교 결과 화면 개선 요청

- 상태: **진행 중 — 주요 UI 검증 완료, 오류 경로 일부 미검증**
- 검증일: 2026-10-15
- 범위: Electron 버전 비교 선택기와 비교 결과의 개요·상세·저장 결과 화면
- 기준: [SPEC §8.6 `DIF-019`~`DIF-027`](../SPEC/03-diff-edit.md#spec-diff-base) · [요청 목차](./README.md)
- 기존 [Phase 03 ROADMAP](../ROADMAP/Phase03.md), [GOAL](../GOAL/Phase03.md), [REVIEW](../REVIEW/Phase03.md)의 완료 기록은 유지한다. 해당 기록을 이 요청의 검증 근거로 재사용하지 않았다.

## 요청 및 수용 계약

1. 비교 선택기는 화면에서 **현재 버전 → DIFF → 기준 버전** 순서로 표시한다. 현재 버전은 변경 대상 `compareVersion`, 기준 버전은 `baseVersion`이다. 계산 방향, 추가·수정·삭제 의미, `data/diff/<baseVersion>_to_<compareVersion>/` 저장 경로는 기존 기준→대상 의미를 유지한다.
2. 비교 실행 결과는 **개요**와 **상세**로 나눈다. 개요는 전체 변화 규모를 빠르게 판단하고 상세는 실제 레코드와 필드 변화를 검토한다.
3. 개요는 추가·수정·삭제 카테고리별 건수를 표시한다. 선택한 카테고리의 레코드 하나만 전체 개요에서 한 번에 미리 보여주고 카테고리 전환으로 대상을 바꾼다. 개요에는 페이지 이동을 두지 않는다.
4. 상세는 전체·추가·수정·삭제 탭, 검색과 10개 단위 페이지 이동을 제공한다. 추가·삭제 카드는 레코드 전체 JSON을, 수정 카드는 변경 필드별 전체 before/after 값을 잘림 없이 표시한다. 전체 diff 산출물을 한 번에 표시하는 control은 제공하지 않는다.
5. 상세의 검색·페이지 이동·저장 toolbar는 긴 결과를 스크롤해도 접근 가능한 위치에 유지한다.
6. 저장 완료 결과를 다시 열고 입력이 달라진 결과를 명시적으로 교체할 수 있어야 한다. 변경 없음과 검색 결과 없음을 구분한다. 저장 결과 조회 실패와 일반 저장 실패는 오류를 표시하되 같은 입력 컨텍스트의 결과는 재시도를 위해 유지할 수 있다.
7. 버전·파일 선택 변경과 새 비교 시작은 이전 결과를 현재 결과처럼 남기지 않는다. 저장 요청에서 결과와 현재 입력의 hash 불일치가 확인되면 stale 결과를 무효화한다.
8. 모바일 폭에서도 선택기 방향, 개요 카테고리, 상세 검색·페이지 이동·저장과 카드의 전체 값에 접근할 수 있어야 한다. 긴 내용은 잘리지 않고 페이지 전체의 가로 overflow를 만들지 않는다.
9. 제목, 본문, label, 수치, 코드·JSON은 기존 Electron 화면의 타이포그래피 계층과 간격을 따른다.
10. 개요·상세 전환은 앱의 기존 수동 `View` 라우팅을 사용한다. React Router가 설치되어 있지 않으므로 URL deep link는 범위가 아니며 새 상태 관리 또는 routing dependency를 추가하지 않는다.
11. 버전 관리의 하위 탐색에는 `리스트`, `비교`와 형제인 `상세 결과`를 항상 표시하고 활성화한다.
12. `상세 결과`에 직접 진입했지만 현재 비교 결과가 없으면 빈 상태와 정확히 `버전 비교로 이동`인 동작을 표시한다. 개요의 `전체 결과 자세히`도 같은 상세 경로로 이동한다.
13. 앱이 최신 비교 결과를 메모리에 보유하는 동안 개요와 `상세 결과`가 그 결과를 함께 사용한다. 비교 화면은 다른 화면으로 이동해도 mounted 상태를 유지하므로 결과는 버전·파일 선택이 바뀔 때까지 유지한다. 앱 재시작 뒤에는 결과를 복원하지 않는다.

<a id="roadmap"></a>
## ROADMAP — 적용 결과

1. 기존 비교 계산과 저장 경로를 유지하고 선택기 표시를 현재→DIFF→기준으로 정렬했다.
2. 개요의 전체 단일 미리보기와 상세의 전체 탭·검색·10개 단위 페이지 이동을 연결했다.
3. 상세 toolbar를 화면 하단에 고정하고 카드의 전체 레코드·필드 값, 저장 결과 재열기·교체, 빈 상태와 stale 입력 무효화를 연결했다.
4. 기존 수동 `View` 전환을 유지했다. URL deep link와 새 routing dependency는 추가하지 않았다.

## 변경 이력 — 상세 결과 직접 진입 (2026-10-15)

- 버전 관리의 항상 표시·활성화된 형제 하위 항목 `상세 결과`와 직접 진입 빈 상태의 `버전 비교로 이동` 동작을 수용 계약에 추가했다.
- 개요의 `전체 결과 자세히`와 하위 탐색의 `상세 결과`가 같은 수동 `View` 경로를 사용하고, 앱이 보유한 최신 비교 결과를 재사용하도록 범위를 명시했다.
- 비교 화면을 mounted 상태로 유지해 화면 이동 뒤에도 최신 결과를 재사용한다. 버전·파일 선택 변경은 결과를 지우고 앱 재시작은 메모리를 초기화한다.
- 디스크 영속 상태나 새 dependency를 추가하지 않았고 기존 수동 `View` 라우팅을 유지했다. 기존 Phase 03 완료 기록은 변경하지 않는다.

<a id="review"></a>
## REVIEW — 부분 검증 (2026-10-15)

- Electron production build와 lint가 exit 0이었다. Vitest 21개 파일·167개 테스트가 통과했다.
- native Electron `verify-diff-playwright.mjs`가 desktop 1480px·mobile 390px에서 통과했다. 선택기는 현재 작업 버전→DIFF→비교 기준 순서였고 표시된 결과는 기준→대상 의미를 유지했다.
- 개요는 추가·수정·삭제 건수와 선택 카테고리의 레코드 하나만 전체 개요에 표시했다. 개요 페이지 이동은 없다. 상세는 전체·추가·수정·삭제 탭, 검색 결과 없음, 10개 단위 페이지 이동, 추가·삭제 전체 레코드와 수정 필드 before/after 값을 확인했다. 긴 중첩 값도 잘리지 않았다.
- 전체 diff 산출물을 표시하는 control은 없다. JSON 검증 범위는 추가·삭제 카드의 전체 레코드와 수정 카드의 전체 before/after 필드 값이다.
- desktop/mobile 상세 toolbar는 화면 하단에 고정되어 문서 중간과 끝 스크롤에서 viewport 안에 남았다. 페이지 전체 가로 overflow는 없었고 개요·상세의 파일명·버전 글자 크기가 viewport별로 같았다.
- 저장·재열기, 입력 변경 뒤 취소·명시적 교체, 파일·버전 선택 변경과 stale 입력 뒤 결과 무효화, 변경 없음의 카테고리별 빈 상태, 검색 결과 없음과 관리 JSON 누락 오류를 확인했다.
- 저장 결과 조회 실패와 일반 저장 실패의 오류 표시·같은 입력 컨텍스트 결과 유지 동작은 이번 native 검증에서 확인하지 않았다.
- 173,665개 삭제 비교는 비교 1,507ms, 검색 252ms, 페이지 이동 50ms였다. 한 페이지에는 10개 카드만 렌더링했다.
- native Electron `verify-version-ui-playwright.mjs`도 통과했다. 주변 route와 모바일 아이콘 geometry 회귀를 확인했다.
- URL deep link는 검증 대상이 아니다. 기존 수동 `View` 라우팅을 유지했고 React Router나 새 routing dependency를 추가하지 않았다.
- 기존 Phase 03 완료 상태는 변경하지 않았다.

### 후속 변경 REVIEW — native 검증 완료 (2026-10-15)

- native Electron `verify-diff-playwright.mjs`가 desktop 1480px·mobile 390px에서 직접 상세 진입의 빈 상태와 정확히 `버전 비교로 이동`인 CTA, 개요의 `전체 결과 자세히` 버튼을 통한 대체 진입을 확인했다.
- 비교 뒤 dashboard와 리스트를 다녀와도 같은 결과가 유지됐다. IPC 비교 호출 counter가 증가하지 않아 재계산하지 않았음을 확인했다. 버전·파일 선택 변경은 결과를 지우고 프로세스 재시작은 메모리를 초기화한다.
- 상세 검색·필터·페이지 이동·저장과 긴 문서의 중간·끝 스크롤에서도 접근 가능한 control을 desktop·mobile에서 확인했다. `verify-version-ui-playwright.mjs`도 통과했다.
- 디스크 영속 상태나 새 dependency를 추가하지 않았고 기존 수동 `View` 라우팅을 유지했다. 저장 결과 조회 실패와 일반 저장 실패의 오류 표시·같은 입력 컨텍스트 결과 유지는 계속 미검증이다.
