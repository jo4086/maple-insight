# REQ002 — 새 직업 분류 초안 흐름

## 목적

저장된 신규 직업 diff를 공유 직업 ID 분류 규칙으로 판별하고, 허용 가능한 신규 직업만 기존 복구 초안 흐름에 안전하게 연결한다. 모호하거나 미분류인 값은 자동 확정하지 않고 수동 검토 근거를 제공하며, 신규 금지 분류는 저장 경계에서도 차단한다.

- Phase 상태: [Electron ROADMAP](../ROADMAP.md#req002-phase01)
- 역사적 배경: [직업 데이터 탭 복구 초안 요청](../REQUESTS/job-data-tab.md)
- 기존 Electron 사양: [Phase 4 직업·스킬 편집](../SPEC/06-phase-03-06.md#spec-phase-04-jobs)
- 공유 규칙: [Core `REQ001`](../../../../packages/game-data/core/docs/REQUIREMENTS/REQ001.md) · [분류기](../../../../packages/game-data/core/src/taxonomy/job-id-classifier.ts) · [Core 목표](../../../../packages/game-data/core/docs/GOAL/REQ001/Phase01.md) · [Core 검토](../../../../packages/game-data/core/docs/REVIEW/REQ001/Phase01.md)

역사적 요청은 배경만 제공한다. 이 요구사항은 Core `REQ001`의 미완료 결정을 대신하거나 Core `REQ001-Phase01`, 기존 Electron Phase 04의 완료 근거가 되지 않는다.

## 범위

- 저장된 버전별 `ms_job.json` diff의 `add`를 공유 `classifyJobId`로 분류한다. 새 diff를 자동 생성하지 않으며 저장된 diff가 없는 버전은 알림 대상이 아니다.
- 알려진 `job`과 검토가 필요한 `unknown`만 신규 직업 후보로 유지한다. `dummy`, `skillGroup`, `system`, `invalid`는 알림과 신규 초안 생성에서 제외한다.
- `job.ambiguous`와 `unknown`은 숨기지 않고 검토 사유를 표시한다. 특히 접두어 `19` 레테 미분류 값은 수동 입력과 검토를 요구한다.
- 분류 결과가 충돌 없는 단일 직업군일 때만 직업군을 제안한다. 접두어 소속이 기존 선택지와 안전하게 일치하고 종족·소속 예외가 없을 때만 소속을 제안한다.
- 기존 저장 초안은 모든 제안보다 우선한다. 원본 `jobID`와 앞자리 0을 보존하고 분류용 5자리 ID를 저장 ID로 바꾸지 않는다.
- 현재 `JobDraft` 계약에 필드가 없는 전직 차수, 종족, 복수 직업군은 설명으로만 표시한다. 임의 필드 추가나 저장을 하지 않는다.
- 신규 초안 저장 경계에서 금지 분류를 다시 거절한다. 기존 DB 직업과 기존 복구 초안의 레거시 값은 재열기·재저장을 막지 않고, `unknown` 초안은 수동 검토 대상으로 보존한다.
- 자동·수동 저장, revision 충돌, 재열기, 무기 후보 staging, 저장 실패와 미저장 이동 경고의 기존 동작을 유지한다.

현재 구현 경계는 [알림 모델](../../src/renderer/src/features/jobs/job-model.ts), [목록 화면](../../src/renderer/src/features/jobs/JobDataView.tsx), [편집 화면](../../src/renderer/src/features/jobs/JobEditView.tsx), [저장 서비스](../../src/main/services/job-data.ts), [초안 계약](../../src/shared/job-data.ts)이다.

## 범위 제외와 제약

- 실제 DB 쓰기, 자동 diff 생성, taxonomy 누락값 자동 확정, 스킬 데이터 편집을 하지 않는다.
- 전직 차수, 종족, 복수 직업군을 새 필드로 저장하지 않는다.
- 기존 Electron Phase 04와 Core `REQ001-Phase01`의 상태나 체크 항목을 변경하지 않는다.
- 열린 선택은 구현 승인으로 간주하지 않는다.

버전 의존성은 이미 저장된 raw diff와 현재 버전의 복구 초안이다. `1.2.419` 원본 341건의 읽기 전용 과거 audit에서는 알려진 직업 254건, 미분류 17건(레테 6건 포함), 더미 17건, 스킬 그룹 9건, 시스템 ID 44건이 확인됐다. 이 수치는 후보·경고 정책의 근거일 뿐 이 요구사항, Electron Phase 04 또는 Core `REQ001-Phase01` 완료 근거가 아니다.

## 수용 기준

- [ ] 저장된 신규 직업 diff 알림이 공유 분류 결과에 따라 `job`·`unknown` 후보와 제외 대상을 정확히 구분한다.
- [ ] 모호한 직업과 미분류 직업이 숨겨지거나 자동 확정되지 않고 수동 검토 사유와 함께 표시된다.
- [ ] 충돌 없는 단일 직업군과 안전한 소속만 제안되며 기존 초안, 원본 ID와 앞자리 0이 보존된다.
- [ ] 신규 금지 분류 저장은 backend 경계에서 차단되고 기존 DB 직업·복구 초안의 레거시 값과 `unknown` 초안의 저장·재열기는 유지된다.
- [ ] 자동·수동 저장, revision 충돌, 재열기, 무기 후보 staging, 저장 실패와 미저장 이동 경고의 회귀 및 desktop·mobile 화면 흐름이 검증된다.
- [ ] 실제 DB 쓰기, 자동 diff 생성, 차수·종족·복수 직업군 저장과 스킬 편집이 발생하지 않는다.

## 열린 결정

- 접두어 `19` 레테의 정식 taxonomy 매핑과 직업군·종족·소속 값
- 공용 ID `3001`의 판정에 필요한 추가 문맥
- 예상된 비직업 코드와 실제 검토 대상을 구분할 기존 validation 경고 정책
