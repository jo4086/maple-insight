### 8.11 DB dry-run과 반영

- `DB-001` `MUST`: 실제 DB 반영 전에 dry-run을 실행해야 한다.
- `DB-002` `MUST`: dry-run은 예상 추가, 수정, 삭제 수와 실패 원인을 제공해야 한다.
- `DB-003` `MUST`: 사용자의 명시적 승인 없이는 publish를 실행하지 않아야 한다.
- `DB-004` `MUST`: 하나의 버전 publish는 가능한 한 단일 트랜잭션으로 처리해야 한다.
- `DB-005` `MUST`: publish 실패 시 부분 반영을 롤백하고 버전 상태를 `failed`로 기록해야 한다.
- `DB-006` `MUST`: 성공한 publish만 버전 상태를 `ready`로 변경해야 한다.
- `DB-007` `SHOULD`: 재시도 가능한 오류와 데이터 수정이 필요한 오류를 구분해야 한다.
- `DB-008` `MUST`: renderer는 Prisma나 DB 연결을 직접 사용하지 않아야 한다.

### 8.12 타입 및 정적 데이터 생성

- `GEN-001` `MUST`: DB에 반영된 ready 버전을 기준으로 타입과 정적 데이터를 생성해야 한다.
- `GEN-002` `MUST`: 생성 명령, 대상 버전, 결과 경로를 실행 전에 표시해야 한다.
- `GEN-003` `MUST`: 생성 결과를 Git diff로 검토하기 전 자동 커밋하지 않아야 한다.
- `GEN-004` `MUST`: 생성 실패가 DB 데이터를 되돌렸다고 오인하게 표시되어서는 안 된다.
- `GEN-005` `SHOULD`: 생성된 파일 수, 변경 파일 수, 오류를 요약해야 한다.
- `GEN-006` `SHOULD`: 데이터 적재와 생성 작업의 의존 순서를 명시적으로 실행해야 한다.

### 8.13 작업 이력과 복구

- `LOG-001` `MUST`: 가져오기, 검증, dry-run, publish, 생성 작업의 시작과 결과를 기록해야 한다.
- `LOG-002` `MUST`: 로그에 API 키, DB 비밀번호 등 비밀값을 기록하지 않아야 한다.
- `LOG-003` `SHOULD`: 실패 작업을 동일한 입력과 설정으로 재실행할 수 있어야 한다.
- `LOG-004` `SHOULD`: 작업 취소 시 현재 단계와 정리 결과를 표시해야 한다.
- `LOG-005` `MAY`: 이전 작업 결과와 diff 보고서를 앱에서 다시 열 수 있다.
