## 사용자 결과

직업·스킬·장비·무기 유형·피해 규칙 작업본을 DB에 저장하기 전에 추가·수정·삭제 건수와 오류를 확인한다. 사용자가 대상 버전과 삭제 범위를 명시적으로 승인했을 때만 반영한다.

## 구현 범위

- [ ] 현 `GameJob`, `GameSkill` 계열, `EquipmentItem`과의 관계를 검토해 보강 metadata·스킬 유형/규칙·무기 유형·장비 증거·승인 이력을 위한 DB migration을 정의한다. 기존 raw 식별자는 바꾸지 않는다.
- [ ] nullable 확장 → 기존 데이터 backfill → 읽기 전환 → 필수 제약 강화 순서로 이행하고 기존 버전의 보강 누락을 다룬다.
- [ ] dry-run은 DB를 수정하지 않고 작업본 해시, 예상 변경, 참조·중복 오류 및 대상 버전 상태를 제시한다.
- [ ] publish 전에 같은 해시의 dry-run 결과, 대상 버전, 삭제 범위를 다시 보여주고 명시적 승인을 받는다. 편집·입력 해시 변경 시 승인을 무효화한다.
- [ ] 가능한 한 버전 단위 트랜잭션으로 반영한다. 실패 시 변경을 롤백하고 버전을 `failed`로 기록하며 성공 전에는 `ready`로 전환하지 않는다. 실패한 작업본과 검토 기록을 보존한다.
- [ ] 성공·실패·재시도와 처리 건수·오류를 기록하되 비밀값·스크린샷 원본은 로그에 남기지 않는다.

## 완료 조건

- [ ] dry-run 전후 DB 상태가 같다. 승인 전 요청과 다른 해시·버전·삭제 범위는 반영되지 않는다.
- [ ] 중간 실패는 부분 DB 반영 없이 롤백되고 버전이 `failed`가 된다. 승인된 재시도는 중복을 만들지 않는다.
- [ ] 직업·스킬·장비·무기 유형·피해 규칙의 참조가 저장 후 조회에서도 일치한다.
- [ ] 실제 Electron 승인 흐름과 실패 복구를 검증하고 [REVIEW](../REVIEW.md)에 기록한다.
