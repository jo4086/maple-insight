# REQ002-Phase01 — 새 직업 분류 초안 흐름

## 목적과 선행 조건

[REQ002 요구사항](../../REQUIREMENTS/REQ002.md)의 분류, 안전한 제안, 저장 경계와 회귀 보존을 구현하고 검증한다. Phase 상태는 [ROADMAP의 `REQ002-Phase01`](../../ROADMAP.md#req002-phase01)만을 기준으로 한다.

- [ ] 공유 [Core `REQ001-Phase01` 목표](../../../../../packages/game-data/core/docs/GOAL/REQ001/Phase01.md)에서 이 단계가 소비할 분류 규칙과 미완료 결정을 확인한다.
- [ ] 기존 [직업 데이터 탭 복구 초안](../../REQUESTS/job-data-tab.md)의 저장·재열기 경계와 [Electron Phase 04](../Phase04.md)의 미완료 상태를 보존한다.
- [ ] 열린 결정은 자동 확정하지 않고 수동 검토 경계로 유지한다.

## 구현 조건

### 알림 후보 분류

- [ ] `newJobsFromComparison`이 공유 분류기를 사용해 `job`·`unknown`만 보존하고 `dummy`, `skillGroup`, `system`, `invalid`를 제외한다.
- [ ] 모호한 알려진 직업, 모든 미분류 값, 빈 직업 이름에 검토 필요 상태와 원본 분류 근거를 전달한다.
- [ ] 여러 이전 버전 알림에 같은 ID가 반복돼도 현재 버전의 동일 초안을 재사용한다.

### 안전한 제안과 표시

- [ ] 해석용 ID, 접두어, 직업군 후보, 차수·분기, 예외·모호성 근거를 편집 화면에 표시한다.
- [ ] 단일 직업군과 안전한 소속만 제안하고 기존 초안과 원본 ID를 우선한다.
- [ ] 데몬 `03`·`19`, 시그너스의 미하일 `05`, 제논 복수 직업군, 에반 빈 이름과 미분류 값은 수동 선택으로 남긴다.
- [ ] taxonomy에 있는 초월자·프렌즈 월드가 필요한 선택지에만 반영되도록 기존 데이터와 대조한다.

### 저장 경계와 회귀 보존

- [ ] 신규 `dummy`, `skillGroup`, `system`, `invalid` 초안을 backend에서도 거절한다.
- [ ] 기존 DB 직업·복구 초안과 `unknown` 초안의 저장·재열기를 보존하며 신규 금지 분류만 차단한다.
- [ ] 무기 후보 검증, revision 충돌, 자동·수동 저장과 미저장 경고의 기존 동작을 보존한다.

## 검증 및 완료 조건

- [ ] 분류 단위 테스트에서 에반 `2200`·`2211`·`2214`·`2217`·`2220`, 레테 미분류, `3001` 모호성, `7000`~`9999`·`2210` 더미, `40000`·`50007` 스킬 그룹, 6자리 시스템 ID와 앞자리 0 보존을 확인한다.
- [ ] backend 테스트에서 신규 금지 후보 거절, 기존 레거시 저장, 미분류 초안 보존을 확인한다.
- [ ] Core/Electron 테스트, Node·Web 타입 검사, lint, Prettier와 production build를 실행하고 결과를 기록한다.
- [ ] Playwright Chromium 모의 데이터로 desktop·mobile 흐름을 확인한다.
- [ ] DB 연결이 가능할 때 native Electron에서 저장된 diff 알림 → 상세 → 수동 입력·무기 후보 → 저장·재진입, 제외·모호 표시, 저장 실패·이동 경고와 인접 화면 이동을 확인한다.
- [ ] 저장된 신규 직업 diff 알림이 허용 후보와 제외 대상을 정확히 구분하고, 모호한 직업과 미분류 직업을 수동 검토 사유와 함께 표시한다.
- [ ] 안전한 직업군·소속만 제안되며 기존 초안, 원본 ID와 앞자리 0이 보존된다.
- [ ] 신규 금지 분류 저장은 차단되고 기존 레거시·미분류 초안의 저장과 재열기는 유지된다.
- [ ] 저장·재열기·무기 후보·미저장 경고 회귀와 desktop·mobile 화면 흐름을 검증한다.
- [ ] 실제 DB 쓰기, 자동 diff 생성, 차수·종족·복수 직업군 저장과 스킬 편집이 발생하지 않음을 확인한다.
- [ ] 열린 결정, 미검증 범위와 기존 Electron Phase 04·Core `REQ001-Phase01` 상태 보존을 확인한다.

구현과 검증 근거가 생기기 전에는 항목을 완료 처리하지 않는다. 별도 REVIEW 문서는 검증 결과가 생길 때 만든다.
