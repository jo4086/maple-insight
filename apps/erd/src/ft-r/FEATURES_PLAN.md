# ERD Features Plan

## 목표

- 기존 구현을 기준으로 이어붙이지 않고, `features` 중심 구조로 ERD 앱을 다시 설계한다.
- 첫 단계에서는 구현보다 설계 기준을 먼저 고정한다.
- 이 문서는 목표, 제약, 화면 규칙, 상태 전이, 구현 순서, 파일 분해 원칙을 정의한다.

## 핵심 원칙

- 파일은 세분화한다.
- 도메인, 파생 계산, UI, 상태, 이벤트 처리를 한 파일에 몰아넣지 않는다.
- 문서 원본 상태와 화면용 파생 상태를 분리한다.
- 구현 순서는 `문서 -> 엔티티 -> 편집기 상태 -> relation -> canvas 보조 기능` 순으로 진행한다.
- 한 번에 전부 만들지 않고, 고정해야 할 규칙부터 확정한다.

## 현재 화면 목표

- 캔버스 위에 테이블을 자유롭게 배치할 수 있어야 한다.
- 테이블은 선택, 행 선택, 행 편집, 행 순서 이동, relation 포트 지정이 가능해야 한다.
- 좌측 툴바와 우측 액션 버튼, 미니맵, 줌, 엔티티 이동 리스트를 포함한 편집기 화면을 구성해야 한다.

## 레이아웃 규칙

### 캔버스

- 캔버스는 그리드 기반이다.
- 캔버스 이동은 휠 클릭으로 가능해야 한다.
- 캔버스 이동 전용 손 모드가 존재해야 한다.
- 줌 기능이 있어야 한다.
- 미니맵이 있어야 한다.
- 미니맵은 토글 가능해야 한다.

### 테이블

- 테이블 width와 height는 `6px` 단위로 조절한다.
- 테이블의 relation 진입 포트와 출구 포트도 `6px` 단위로 지정한다.
- 테이블 간 기본 배치는 서로 떨어뜨리는 마진 없이 붙여서 배치 가능한 구조여야 한다.
- 좌측 상단에는 테이블명, 우측 상단에는 테이블 별칭이 위치한다.
- 테이블 헤더 아래에는 컬럼 헤더가 존재한다.
- 컬럼 헤더 순서는 `key`, `name`, `pname`, `domain`, `type`, `null`, `default`, `comment` 이다.
- 행 텍스트는 줄바꿈이 없어야 한다.

### 테이블 선택 상태 UI

- 테이블 아무데나 클릭하면 테이블이 선택된다.
- 테이블 선택 상태에서는 액션 아이콘이 보여야 한다.
- 테이블 선택 액션은 `속성`, `팔레트`, `삭제`, `PK 추가`, `일반 필드 추가`를 포함한다.

### 행 선택 상태 UI

- 테이블이 선택된 상태에서 특정 행을 클릭하면 해당 행이 추가 선택된다.
- 행이 선택되면 좌측에 드래그 앤 드롭 핸들이 보여야 한다.
- 행이 선택되면 우측에 `속성 버튼`, `삭제 버튼`이 보여야 한다.

### 행 편집 상태 UI

- 행이 선택된 상태에서 행 내부 인풋을 더블클릭하면 해당 행이 편집 상태로 전환된다.
- 편집 상태에서 `ESC`를 누르면 편집이 취소되고 행 선택 상태로 되돌아가야 한다.

## 행 정렬 규칙

- 행은 드래그 앤 드롭으로 위아래 이동 가능해야 한다.
- 단, 상위 고정 정렬 규칙이 존재한다.
- 고정 순서는 `PK -> 식별 외래키 -> 일반키 또는 비식별 외래키` 이다.
- 드래그 앤 드롭은 이 고정 규칙을 깨면 안 된다.
- 즉, 사용자는 같은 그룹 내부에서 자연스럽게 순서를 이동할 수 있어야 하고, 그룹 경계는 시스템이 보호해야 한다.

## relation 규칙

- 테이블에는 relation 진입 포트와 출구 포트가 필요하다.
- 포트 위치는 `6px` 단위 스냅 기준으로 관리한다.
- 포트는 테이블 레이아웃이 확정된 이후 계산 가능해야 한다.
- relation은 엔티티 원본 데이터와 직접 섞기보다 파생 계산 계층에서 해석하는 방향이 안전하다.

## 우측 액션 버튼 영역

- 우측 상단에는 액션 버튼 그룹이 존재한다.
- 액션 버튼을 클릭하면 아래 항목들에 접근 가능해야 한다.
- `미니맵 토글`
- `현재 엔티티 리스트`
- `DDL 프리뷰`
- `테이블 간단 이미지 변환 토글`
- 현재 엔티티 리스트에서 특정 엔티티를 클릭하면 해당 엔티티 위치로 캔버스가 이동해야 한다.

## 좌측 툴바

- `테이블 추가`
- `메모 추가`
- `관계 추가`
- `캔버스 무빙 전용 손 아이콘`

## 구현 우선순위

### 1단계: 문서 구조와 제약 정의

- `ErdDocument` 구조 확정
- 엔티티, 필드, 메모, 선택 상태에 필요한 최소 타입 정의
- 그리드 단위 상수 정의
- 테이블/행 상태 전이 규칙 정의

### 2단계: 엔티티 도메인과 레이아웃 계산

- 엔티티 원본 데이터 구조 확정
- 컬럼 정의 확정
- 행 높이, 헤더 높이, 전체 width/height 계산
- `6px` 스냅 규칙 반영
- 포트 배치 규칙 초안 정의

### 3단계: 테이블 정적 UI

- 테이블 헤더 렌더
- 컬럼 헤더 렌더
- 행 렌더
- 줄바꿈 금지 처리
- 테이블 액션 버튼 위치 규칙 반영

### 4단계: 선택 상태

- 테이블 선택
- 행 추가 선택
- 선택 상태별 UI 노출 분기

### 5단계: 행 편집 상태

- 더블클릭 편집 진입
- 편집 종료
- `ESC` 취소
- 편집 중 포커스 규칙

### 6단계: 행 드래그 앤 드롭

- 드래그 핸들 기반 시작
- 같은 그룹 내부 재정렬
- 그룹 경계 보호
- 자연스러운 미리보기 이동

### 7단계: relation derive와 포트

- 필드 기반 relation 해석
- 포트 진입/출구 계산
- relation용 데이터 구조 생성

### 8단계: 캔버스 보조 기능

- 줌
- 휠 클릭 팬
- 손 모드
- 미니맵
- 엔티티 리스트 이동
- DDL 프리뷰
- 간단 이미지 토글

## 상태 전이 초안

### 테이블 기준

- 기본 상태: 미선택
- 클릭: 테이블 선택
- 선택 상태에서 행 클릭: 행 선택 추가

### 행 기준

- 기본 상태: 미선택
- 클릭: 선택
- 선택 상태에서 더블클릭: 편집 상태
- 편집 상태에서 `ESC`: 선택 상태로 복귀

## 파일 분해 원칙

- `document`
  - 문서 타입
  - 문서 초기값
  - 문서 단위 명령
- `entity/model`
  - `Entity`, `EntityField` 같은 원본 도메인 타입
- `entity/layout`
  - 엔티티 크기 계산
  - 포트 위치 계산
  - 컬럼/행 레이아웃 계산
- `entity/ui`
  - 테이블 박스
  - 헤더
  - 컬럼 헤더
  - 행
  - 액션 버튼
- `entity/interaction`
  - 클릭
  - 더블클릭
  - 드래그 시작 규칙
- `editor/context`
  - 선택 상태
  - 편집 상태
  - 도구 모드
- `relation/model`
  - relation 타입
- `relation/derive`
  - 엔티티/필드로부터 relation 계산
- `relation/ui`
  - relation 렌더
- `canvas`
  - 줌
  - 팬
  - 미니맵
  - 엔티티 리스트 이동

## 초기 결정이 필요한 항목

- `domain`과 `type`을 분리할지 여부
- 테이블 최소 width와 최소 height
- row height 고정값
- header height 고정값
- 포트 표시 방식과 포트 활성 조건
- 식별 외래키와 비식별 외래키의 판별 기준
- DDL 프리뷰 생성 범위
- 간단 이미지 토글 시 축약 컬럼 범위
