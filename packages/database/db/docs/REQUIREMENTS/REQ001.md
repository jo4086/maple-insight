# REQ001: Weapon Types DB 설계 및 구현 요구사항

- **현재 사용자 결정:** [`weapon-types-request.md`](../REQUESTS/REQ001/weapon-types.md)
- **동작 명세:** [`REQ001-01`](../SPEC/REQ001/weapon-types.md)

## 1. 범위와 원칙

`equipment.weapon_types`는 무기 타입별 기본 착용 범위와 기본 무기상수, 필요한 직업별 최종 무기상수를 관리한다.

- 아이템별 착용 조건이 없으면 타입 기본값을 사용하고, 있으면 합치지 않고 완전히 대체한다.
- 공격속도는 `equipment.weapon_types`가 소유한다. 주무기는 nullable `attack_speed` `SMALLINT`를 사용하며 non-null 값은 `1..8`, 보조무기는 `NULL`이다.
- 무기상수 예외를 위한 새 테이블이나 boolean을 추가하지 않는다.
- 직업별 무기상수는 nullable `weapon_constant_overrides` JSONB 배열 하나로 표현한다.
- 직업 전용 `jobId`는 현재 seed에 지정하지 않고 직업 데이터에서 추후 파생한다.

## 2. 현재 테이블 계약

실제 컬럼명과 타입은 Prisma schema와 migration을 기준으로 한다.

| 컬럼 | 타입 | Nullable | 계약 |
| --- | --- | --- | --- |
| `id` | BIGINT | NO | 전역 PK |
| `part` | TEXT | NO | 표시 파츠명 |
| `normalized_part` | TEXT | NO | 공백 제거 파츠명 |
| `category` | TEXT | NO | `weapon` / `subWeapon` |
| `hand_type` | TEXT | YES | 주무기만 `oneHanded` / `twoHanded` |
| `class_group_keys` | TEXT[] | NO | 기본 직업군 |
| `allowed_job_ids` | TEXT[] | NO | 명시적 직업 ID 목록 |
| `availability_mode` | TEXT | NO | 기본 착용 범위 모드 |
| `is_dedicated` | BOOLEAN | NO | 전용 여부 |
| `weapon_constant` | DECIMAL | YES | 주무기 기본값 |
| `weapon_constant_overrides` | JSONB | YES | 직업별 최종값 배열 |
| `attack_speed` | SMALLINT | YES | 주무기 `1..8` 또는 `NULL`, 보조무기 `NULL` |

`(category, normalized_part)`는 unique다. 주무기는 hand type과 양수 기본 상수가 필요하고, 보조무기는 주무기 전용 필드를 SQL `NULL`로 둔다.

## 3. 무기상수 예외 계약

- SQL `NULL`은 예외 없음이다.
- non-null 값은 하나 이상의 `{ "jobId": string, "weaponConstant": string }` 객체로 구성된 JSON 배열이다.
- `jobId`는 비어 있지 않고 배열 안에서 유일해야 한다. `weaponConstant`는 양수 decimal 문자열이며 보정치가 아닌 최종값이다.
- 객체 한 개짜리 배열은 허용하지만 배열이 아닌 단일 직업·값 scalar pair는 거부한다. 한손둔기는 히어로와 팔라딘 두 항목을 동시에 가져야 한다.
- 별도 예외 테이블과 예외 존재 boolean은 만들지 않는다.

확정된 값은 다음과 같다.

| 무기 타입 | 기본값 | 직업별 예외 |
| --- | --- | --- |
| 한손검 | `1.24` | hero `1.34` |
| 한손둔기 | 기존 원천값 | hero `1.34`, paladin `1.24` |
| 두손검 | 기존 원천값 | hero `1.44` |
| 두손둔기 | 기존 원천값 | hero `1.44` |
| 샤이닝 로드 | `1.2` | 없음 |
| 에너지 소드 | `1.3125` | 없음 |

2026-11-02 설계의 `hero_weapon_constant` 전용 컬럼과 히어로 도끼 예외는 2026-11-03 사용자 결정으로 대체되었다. 당시 증거는 [`REVIEW.md`](../REVIEW.md)에 역사 기록으로 보존한다.

## 4. 착용 범위

1. 아이템별 조건이 없으면 무기 타입 기본값을 사용한다.
2. 아이템별 조건이 있으면 기본값과 합치지 않고 완전히 대체한다.
3. 명시적 공용과 조건 없음은 구별한다.
4. 요구 레벨만으로 착용 가능 직업군을 결정하지 않는다.
5. 현재 36행 seed의 `allowedJobIds`는 비우며 dedicated job 지정은 추후 직업 데이터에서 파생한다.

## 5. Seed 원천과 충돌 경계

- 사용자 제공 원천은 `packages/game-data/equipment/data/weapon-types.json` 단일 파일이다.
- 원천은 카르타를 포함한 36행이다. 기존 정적 정의 35종은 더 이상 최종 seed 원천이 아니다.
- 입력은 JSON 배열, unique `(category, normalizedPart)`, 카테고리별 필수값, 직업군 코드, override 배열 형태와 값, 36개 정수 `attackSpeed` 값의 `1..8` 범위를 검증해야 한다.
- 동일한 기존 행은 ID를 유지하고 건너뛴다. 같은 key의 값이 다르면 임의 덮어쓰기 없이 전체 write 전에 충돌로 거부한다.
- 기존 DB 행이 있으면 36행 원천과 충돌할 수 있다. 갱신·보존 방침은 별도 사용자 확인 전 결정하지 않고 seed를 실행하지 않는다.

## 6. Migration과 데이터 보존

`20261104000000_replace_hero_weapon_constant_with_overrides`는 기존 non-null `hero_weapon_constant`를 `hero` override 배열로 옮긴 뒤 구 컬럼을 제거하도록 작성되었다. 기존 도끼 값도 그대로 옮겨 데이터 손실을 피한다. 이 보존 결과와 현재 36행 원천이 다를 수 있으므로 실제 기존 행 처리 방침은 별도 확인이 필요하다.

2026-11-03의 공격속도 제거 결정과 `20261103000000_remove_weapon_type_attack_speed`는 날짜가 있는 이력으로 보존한다. 현재 계약은 이후 사용자 정정으로 대체되었고, `20261105000000_restore_weapon_type_attack_speed`가 nullable `attack_speed SMALLINT`와 주무기 `NULL` 또는 `1..8`·보조무기 `NULL` CHECK를 additive migration으로 다시 추가한다. 기존 행은 migration만 적용하면 `NULL`을 유지한다. 기존 같은 key 행의 `NULL`과 36행 원천의 숫자는 충돌이므로 seed가 조용히 갱신하지 않는다.

Migration 작성, 실제 DB 적용, seed 실행은 서로 다른 상태다. 사용자가 migration을 독립적으로 적용했으며, read-only `prisma migrate status`에서 대상 `localhost:5432/maple_ingestor`의 `app`, `equipment`, `game_data`, `ranking` schema에 18개 migration이 모두 적용된 상태를 확인했다. Assistant는 `migrate deploy`를 실행하지 않았다. 사용자 승인 아래 최초 seed가 36행을 삽입했지만 재실행, FK/backfill과 그 밖의 DB 불변식은 검증하지 않았다.

## 7. 완료 조건

- 현재 JSONB 배열 계약과 확정값이 schema, validation, resolver, seed 원천에서 일치해야 한다.
- 일반 직업은 기본값, override가 있는 직업은 해당 최종값을 사용해야 한다.
- 아이템별 착용 override와 FK 없는 레거시 fallback 회귀를 검증해야 한다.
- 36행 원천, 카르타, 각 행의 사용자 제공 숫자 `attackSpeed`를 검증해야 한다.
- 실제 DB migration과 seed는 각각 별도 승인과 실행 증거가 있어야 완료로 기록할 수 있다.
- 타입 검사, 린트, 관련 테스트 결과는 실행한 것만 [`REVIEW.md`](../REVIEW.md)에 기록한다.
