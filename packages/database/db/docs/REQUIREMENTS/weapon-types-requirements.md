# REQ001: Weapon Types DB 설계 및 구현 요구사항

## 1. 개요

`equipment.weapon_types`는 무기 타입별 기본 속성과 착용 가능 직업군, 무기상수를 관리한다.

### 설계 원칙

- 무기 타입에는 기본 착용 직업군을 정의한다.
- 개별 아이템은 필요할 때 기본 착용 직업군을 오버라이드할 수 있다.
- 무기상수는 무기 타입별 기본값을 사용한다.
- 히어로의 특정 무기 타입에만 별도 무기상수를 적용한다.
- 불필요한 테이블이나 범용 예외 시스템은 추가하지 않는다.

## 2. 테이블 구조

**대상:** `equipment.weapon_types`

| 컬럼                   | 타입 (예시)    | Nullable | 설명                  |
| ---------------------- | -------------- | -------- | --------------------- |
| `id`                   | INTEGER / UUID | NO       | 기본키                |
| `part`                 | TEXT           | NO       | 무기 파츠명           |
| `normalized_part`      | TEXT           | NO       | 정규화된 파츠명       |
| `category`             | TEXT           | NO       | weapon / subWeapon    |
| `hand_type`            | TEXT           | NO       | oneHanded / twoHanded |
| `class_group_keys`     | TEXT[]         | NO       | 기본 착용 직업군      |
| `availability_mode`    | TEXT           | NO       | 기본 착용 범위        |
| `is_dedicated`         | BOOLEAN        | NO       | 특정 직업 전용 여부   |
| `weapon_constant`      | DECIMAL        | NO       | 기본 무기상수         |
| `hero_weapon_constant` | DECIMAL        | YES      | 히어로 전용 무기상수  |
| `attack_speed`         | INTEGER        | YES      | 기본 공격속도         |

기존 컬럼명과 타입은 실제 Prisma 스키마를 우선한다.

핵심 변경 사항은 `hero_weapon_constant` 컬럼 추가다.

## 3. 시드 데이터 예시

아래 수치는 구조 설명용 예시이며, 실제 게임 데이터와 대조해야 한다.
시드 데이터는 사용자가 차후에 만들어서 줄 예정이다.

| part     | hand_type | class_group_keys | weapon_constant | hero_weapon_constant |
| -------- | --------- | ---------------- | --------------- | -------------------- |
| 한손검   | oneHanded | warrior          | 1.20            | 1.34                 |
| 두손검   | twoHanded | warrior          | 1.34            | 1.44                 |
| 한손도끼 | oneHanded | warrior          | 1.20            | 1.34                 |
| 두손도끼 | twoHanded | warrior          | 1.34            | 1.44                 |
| 한손둔기 | oneHanded | warrior          | 1.20            | NULL                 |
| 두손둔기 | twoHanded | warrior          | 1.34            | NULL                 |
| 창       | twoHanded | warrior          | 1.49            | NULL                 |
| 폴암     | twoHanded | warrior          | 1.49            | NULL                 |

### 시드 데이터 규칙

- 기본 직업군은 무기 타입에 정의한다.
- 히어로 전용 무기상수는 지정된 네 종류에만 설정한다.
- 나머지 무기 타입의 `hero_weapon_constant`는 NULL이다.
- 기존 `packages/game-data/equipment` 정의를 우선 활용한다.
- 확인되지 않은 무기상수는 임의로 생성하지 않는다.

## 4. 착용 가능 직업군 처리

무기 타입에 정의된 기본 직업군은 개별 아이템에서 오버라이드할 수 있다.

| 아이템        | 무기 타입 | 기본 직업군 | 개별 아이템 조건 | 최종 착용 범위   |
| ------------- | --------- | ----------- | ---------------- | ---------------- |
| 일반 한손검   | 한손검    | 전사        | 없음             | 전사             |
| 저레벨 한손검 | 한손검    | 전사        | 공용, 데몬 제외  | 공용, 데몬 제외  |
| 일반 폴암     | 폴암      | 전사        | 없음             | 전사             |
| 저레벨 폴암   | 폴암      | 전사        | 전사, 궁수, 도적 | 전사, 궁수, 도적 |
| 이벤트 폴암   | 폴암      | 전사        | 공용             | 전체 직업        |

### 적용 규칙

1. 개별 아이템에 착용 조건이 없다면 무기 타입의 기본값을 사용한다.
2. 개별 아이템에 착용 조건이 있다면 해당 조건으로 완전히 대체한다.
3. 기본 직업군과 오버라이드 직업군을 자동으로 합치지 않는다.
4. 요구 레벨만으로 착용 가능 직업군을 결정하지 않는다.

## 5. 무기상수 처리

히어로는 다음 네 종류의 무기를 착용할 때만 별도 무기상수를 적용한다.

| 무기 타입  | 히어로 예외 적용 |
| ---------- | ---------------- |
| 한손검     | O                |
| 두손검     | O                |
| 한손도끼   | O                |
| 두손도끼   | O                |
| 그 외 무기 | X                |

### 적용 우선순위

1. 현재 직업이 히어로인지 확인한다.
2. 히어로이고 `hero_weapon_constant`가 NULL이 아니라면 해당 값을 사용한다.
3. 나머지 경우에는 `weapon_constant`를 사용한다.

`hero_weapon_constant`는 기본값에 더하는 보정치가 아니라 최종 무기상수다.

히어로 예외는 과거 게임 시스템에서 유래한 고정 규칙이며 다른 직업으로 확장할 계획이 없다.

따라서 별도 예외 테이블이나 JSONB 기반 범용 오버라이드 구조는 도입하지 않는다.

## 6. 에이전트 작업 지시사항

### 6.1. 사전 확인

작업 전 다음 영역의 기존 구조와 규칙을 확인한다.

- `packages/database/AGENTS.md`
- `packages/database/db`
- `packages/database/data-admin`
- `packages/game-data/equipment`
- 관련 README.md 및 Prisma 스키마

기존 설계와 충돌하는 사항은 임의로 변경하지 않고 보고한다.

### 6.2. DB 및 시드 데이터 구현

- 기존 `equipment.weapon_types` 구조를 최대한 유지한다.
- `hero_weapon_constant` nullable 컬럼을 추가한다.
- 필요한 Prisma 마이그레이션을 작성한다.
- 기존 데이터 손실을 방지한다.
- 무기 타입의 기본 직업군을 정의한다.
- 히어로 예외 대상 네 종류에만 예외 무기상수를 설정한다.
- 시드 데이터는 기존 프로젝트의 무기 타입 정의를 활용한다.
- 기존 시드 데이터와 중복되지 않도록 한다.

### 6.3. 검증

다음 사항을 검증한다.

- 일반 직업은 기본 무기상수를 사용한다.
- 히어로는 지정된 네 종류에서만 예외 무기상수를 사용한다.
- 히어로도 나머지 무기 타입에서는 기본 무기상수를 사용한다.
- 개별 아이템의 착용 조건 오버라이드가 기본 직업군을 대체한다.
- 기존 데이터와 기능에 회귀 문제가 발생하지 않는다.

관련 타입체크, 린트 및 테스트를 수행한다.

### 6.4. 작업 범위 제한

- 새로운 예외 테이블을 생성하지 않는다.
- 무기상수에 JSONB를 도입하지 않는다.
- 불필요한 의존성을 추가하지 않는다.
- 기존 구조를 불필요하게 리팩터링하지 않는다.
- 요구사항과 무관한 파일을 수정하지 않는다.
