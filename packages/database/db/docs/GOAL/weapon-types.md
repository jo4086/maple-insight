# REQ001-P01: 무기 타입 설계 정합성 검토와 승인

- **대상 명세:** [`REQ001-01`](../SPEC/weapon-types.md)
- **상태와 의존성:** [`ROADMAP.md`](../ROADMAP.md)
- **현재 구현 근거:** [`REQUESTS/weapon-types.md`](../REQUESTS/weapon-types.md)

## 산출물

다음 결정을 실제 스키마, migration, 정적 정의와 소비 경로를 대조해 기록한다.

1. 전역 무기 타입과 버전별 `EquipmentItem`을 식별·연결하는 방식
2. 아이템 착용 조건 없음, 명시적 공용 조건, 타입 기본값 완전 대체를 구별하는 방식
3. 기존 아이템 값과 조회·생성 경로의 호환성 및 전환 범위
4. 보조무기 대상 범위, 데이터 출처와 주무기 전용 필드의 `NULL` 규칙
5. 팔라딘 한손둔기 정적 예외를 유지할지 승인된 구조로 전환할지에 대한 선택과 근거
6. 정적 정의, 사용자 제공 최종 seed 데이터, DB 행의 소유권과 검증 기준
7. Migration 파일 작성, migration 적용, seed 실행 각각의 승인 주체와 검증 방법

## 종료 조건

- 모든 산출물의 선택, 근거, 영향 범위가 문서화되어야 한다.
- [`REQ001-01`](../SPEC/weapon-types.md)의 각 수용 조건과 설계 결정의 대응이 확인되어야 한다.
- `db`, `data-admin`, `game-data/equipment`의 책임 경계와 변경 대상이 구분되어야 한다.
- 기존 데이터 보존과 롤백 또는 실패 처리 방법이 확인되어야 한다.
- Migration 적용 승인과 seed 실행 승인이 별도 절차로 정의되어야 한다.
- 설계가 승인되어야 한다.

설계 승인 전 새 DB 구조의 구현이나 적용을 완료로 기록하지 않는다. 이 Phase는 구조를 미리 확정하지 않으며 위 결정을 해결한다.
