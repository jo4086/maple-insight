# REQ001-01: 전역 무기 타입 동작 명세

- **상위 요구사항:** [`REQ001`](../REQUIREMENTS/weapon-types-requirements.md)
- **구현 사실과 미완료 범위:** [`REQUESTS/weapon-types.md`](../REQUESTS/weapon-types.md)
- **검증 이력:** [`REVIEW.md`](../REVIEW.md)

이 문서는 `REQ001`의 수용 조건을 구현·검증 가능한 단위로 구분한다. 요구 규칙과 예시 데이터의 원문은 상위 요구사항이 소유한다.

## 수용 조건

### AC01. 착용 범위

- 무기 타입의 기본 착용 범위가 정의되어야 한다.
- 아이템별 착용 조건이 없으면 타입 기본값을 사용해야 한다.
- 아이템별 착용 조건이 있으면 타입 기본값과 합치지 않고 완전히 대체해야 한다.
- 명시적인 공용 조건과 조건 없음이 구별되어야 한다.
- 요구 레벨은 착용 가능 직업군 결정에 사용하지 않아야 한다.

### AC02. 무기상수

- 일반 계산은 타입의 기본 무기상수를 사용해야 한다.
- 히어로는 상위 요구사항이 지정한 네 무기 타입에서만 nullable 예외값을 최종 상수로 사용해야 한다.
- 예외값이 없거나 히어로가 아니면 기본값을 사용해야 한다.
- 기존 정적 계산의 팔라딘 한손둔기 예외는 호환 방침이 승인되고 회귀 검증되기 전까지 제거하지 않아야 한다.

### AC03. 주무기와 보조무기

- 주무기는 손 타입과 기본 무기상수를 가져야 한다.
- 보조무기는 주무기 전용 속성을 `NULL`로 유지해야 한다.
- 카테고리별 필수값과 `NULL` 규칙은 스키마와 입력 검증에서 일치해야 한다.

### AC04. 데이터 검증

- 기존 정적 정의에서 준비된 주무기 35종은 구현 입력 후보이며 사용자 제공 최종 seed 데이터로 간주하지 않아야 한다.
- 상위 요구사항의 수치 예시는 실제 seed 값으로 간주하지 않아야 한다.
- 사용자 제공 seed 데이터는 출처, 고유성, 참조 무결성, 카테고리별 필수값을 검증해야 한다.
- 동일 입력 재실행은 같은 결과를 보장하고 충돌 데이터를 임의로 덮어쓰지 않아야 한다.

### AC05. 연결과 회귀

- 버전별 `EquipmentItem`은 승인된 방식으로 전역 무기 타입을 식별해야 한다.
- 조회와 계산 경로가 타입 기본값과 아이템별 대체 조건을 일관되게 사용해야 한다.
- 기존 장비 생성·조회·계산 동작의 회귀 여부를 검증해야 한다.
- Migration 적용과 seed 실행은 각각 별도 승인을 받은 뒤 실제 DB에서 검증해야 한다.

## 현재 구현 경계

작성된 모델, migration 파일, 공유 타입, 주무기 35종 기반 seed repository와 CLI 및 정적 검증 결과는 [구현 상태 문서](../REQUESTS/weapon-types.md)에 기록되어 있다. 전역 타입과 `EquipmentItem` 연결, 아이템별 착용 조건 대체, 보조무기와 사용자 제공 최종 seed 데이터, 실제 DB 적용 검증은 완료되지 않았다.
