# REQ001: jobID 분류 검증

## 목적

원본 직업 레코드를 변경하지 않고 `jobID`의 형식, 직업 계열, 직업군, 분기, 전직 단계를 일관되게 판정한다. 판정할 수 없는 값은 폐기하지 않고 검토 대상으로 보고한다.

## 범위

- 소유 패키지: `packages/game-data/core`
- 공유 가능한 순수 분류 규칙과 검증 결과를 정의한다.
- Electron은 향후 공유 규칙을 소비하고 기존 직업 데이터 검증 흐름에 연결한다.
- 원본 레코드와 DB를 수정하지 않는다.
- 생성기와 DB 연동은 후속 작업으로 미룬다.

## 5단계 검증 목표

### 1. 원본 형식 검증

- 입력 `jobID`는 숫자로만 이루어진 1~5자리 문자열이어야 한다.
- 원본 문자열과 선행 0을 그대로 보존한다.
- 6자리 시스템 ID는 사용자 직업 분류에서 제외하되 원본은 보존한다.
- 검증과 분류는 원본 레코드를 변경하지 않는다.

### 2. 해석용 정규화와 접두어 분류

- 분류할 때만 `padStart(5, '0')`을 적용한다.
- 허용 접두어와 사용자 분류명은 다음과 같다.
  - `00`: 모험가
  - `01`: 시그너스 기사단
  - `02`: 영웅
  - `03`: 레지스탕스
  - `05`: 미하일
  - `06`: 노바
  - `10`: 초월자
  - `14`: 프렌즈 월드
  - `15`: 레프
  - `16`: 아니마
  - `19`: 마족
- `07`~`09` 접두어의 `7000`~`9999`는 사용되지 않는 더미 범위로 분류 대상에서 제외한다.
- 현재 예상 범위는 `30000` 미만이지만, 문서화되지 않은 ID를 범위만으로 거부하지 않는다. 알 수 없는 접두어와 `30000` 이상 값은 검토 대상으로 보고한다.
- 접두어 `19`의 레테 ID(`19000`, `19200`, `19210`~`19212`, `19214`)는 원본에서 확인했으나 taxonomy의 직업 매핑이 없으므로 직업으로 자동 확정하지 않고 검토 대상으로 둔다.

### 3. 기본 직업 구조 해석

- 해석용 5자리 값의 마지막 세 자리 중 첫 자리는 기본 직업군을 나타낸다.
  - `0`: 초보자
  - `1`: 전사
  - `2`: 마법사
  - `3`: 궁수
  - `4`: 도적
  - `5`: 해적
- 마지막 세 자리 중 둘째 자리는 2차 전직부터의 분기를 나타낸다.
- 마지막 자리는 기본 전직 진행을 나타낸다.
- 기본 규칙에 맞지 않는 값은 임의 추론하지 않고 명시적 예외나 검토 대상으로 처리한다.

### 4. 명시적 예외 적용

- 루미너스 `02700` 계열처럼 기본 접미 규칙만으로 판정할 수 없는 직업은 명시적 매핑으로 판정한다.
- 에반 원본 레코드는 `2200`, `2211`, `2214`, `2217`, `2220`을 각각 1차, 2차, 3차, 4차, 6차로 판정한다.
- `2220`의 빈 `jobName`은 알려진 원본 상태로 허용하되 보고한다.
- 에반의 `2210`(`마스터2차`), `2212`(`마스터4차`), `2213`(`마스터5차`), `2215`(`마스터7차`), `2216`(`마스터8차`), `2218`(`마스터10차`)는 원본에서 지우지 않고 직업 보강 후보에서 제외한다.
- 6차 전직은 마지막 자리 일반식으로 단정하지 않고 명시적 매핑을 우선한다.
- 듀얼블레이드의 1.5차·2.5차와 공용 원본 ID `3001`을 사용하는 데몬슬레이어·데몬어벤져는 검토 및 fixture로 확정한다.
- ID만으로 lineage를 추론하지 않는다. 데몬 lineage와 레지스탕스 affiliation을 별도 축으로 유지한다.

### 5. 비직업 분류와 보고

- `rawJobCategoryMap`의 정확한 ID `40000`, `40001`~`40005`, `50000`, `50006`, `50007`은 직업 코드가 아닌 스킬 그룹으로 분류한다.
- 해당 ID가 속한 숫자 구간 전체를 스킬 그룹으로 간주하지 않는다.
- 스킬 그룹은 직업 분류와 분리된 결과 범주로 반환하고 원본을 보존한다.
- 향후 정확한 스킬 연결 정책은 이 요구사항에서 확정하지 않는다.
- 결과 보고는 정상 직업, 명시적 예외, 더미, 알 수 없는 값, 스킬 그룹, 사용자 분류 제외를 구분한다.

## 제약

- 현재 `classJobIdMap`과 affiliation·lineage·직업군 taxonomy를 근거 데이터로 사용한다.
- 분류 규칙은 Electron 전용 구현으로 중복하지 않는다.
- 기존 Electron 검증기는 현재 문자열 형식, 중복, 이름, 미정의 필드와 이름 공백을 검사하며 원본 일부를 정규화한다. 공유 분류 규칙 연동은 아직 구현된 동작이 아니다.
- 검증 과정은 원본 파일, 원본 레코드, DB를 변경하지 않는다.

## 미확정 사항

- `3001`의 직업 판정에 필요한 추가 문맥과 fixture
- 듀얼블레이드 1.5차·2.5차 판정 fixture
- 접두어 `19`의 확인된 레테 원본 ID를 taxonomy의 직업명·직업군·차수 매핑으로 확정하는 정책
- 스킬 그룹과 개별 스킬을 연결하는 후속 정책
- 생성기 및 DB 반영 방식

## 인수 조건

- [ ] 1~5자리 숫자 문자열과 선행 0 보존을 검증한다.
- [ ] 분류에만 5자리 왼쪽 0 채우기를 적용하고 원본을 변경하지 않는다.
- [ ] 6자리 시스템 ID, 더미 범위, 알 수 없는 ID를 서로 구분해 보고한다.
- [ ] 허용 접두어, 기본 직업군·분기·전직 규칙을 검증한다.
- [ ] 루미너스, 에반, 듀얼블레이드, 데몬 계열의 명시적 예외와 미확정 항목을 검증한다.
- [ ] 정확한 스킬 그룹 ID만 별도 범주로 분류한다.
- [ ] 알려진 정상값, 예외, 더미, 알 수 없는 값, 스킬 그룹, 원본 보존을 fixture와 테스트로 확인한다.
- [ ] Electron이 공유 순수 분류 규칙을 소비하도록 연결하되 검증 중 원본과 DB를 변경하지 않는다.
