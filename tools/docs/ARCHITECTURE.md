# Skill Image Extractor — 아키텍처 설계 지침

## 1. 설계 목적

현재 준비된 C# CLI 추출기를 Maple Insight의 직업 데이터, 스킬 데이터, Electron 관리 앱과 연결하기 위한 아키텍처를 설계한다.

이 문서는 검증된 C# CLI 이후의 Electron 연동과 저장 구조를 제안한다. 후속 기능은 이 문서만으로 구현 완료로 간주하지 않는다.

## 2. 우선 분석할 영역

- 루트 및 관련 영역의 `AGENTS.md`
- `tools/maple-skill-extractor/`
- Electron Main / Renderer 구조
- 직업 및 전직 ID 연결 데이터
- 스킬 데이터 관리 기능
- 기존 에셋 저장 및 등록 방식
- 환경설정 및 설정값 영속화 방식

관련 Skill을 적용하되 불필요한 전체 프로젝트 스캔은 피한다.

## 3. 주요 설계 검토사항

### 데이터 및 책임 분리

- 대표 jobID에서 전직 jobID를 결정하는 책임
- 전직 jobID에서 skillID를 탐색하는 방식
- C# 추출기와 Electron의 역할 경계
- 이미지 저장과 데이터 등록의 책임
- 기존 데이터베이스 및 패키지 재사용 가능성

### WZ 추출

- `Base.wz → Skill → *.img → skill → {skillID}` 탐색
- jobID와 IMG 파일의 실제 대응 관계 검증
- 공용 및 특수 스킬 처리
- UOL 참조 처리
- 이미지 누락, 중복, 실패 복구
- 추출 완료 상태 관리

### Electron 연동

- Electron Main Process에서 추출기 실행
- Renderer와 Main 간 IPC 설계
- 작업 상태, 진행률, 오류 전달
- 동시 실행 및 중복 작업 방지
- 설정값 저장 및 경로 검증

### 환경별 실행

다음 환경의 실행 시퀀스를 각각 설계한다.

1. WSL Electron → Windows C# 추출기
2. Windows Electron → Windows C# 추출기
3. 자동 실행이 불가능할 때의 수동 CLI 대안

각 방식의 안정성, 유지보수성, 경로 변환 및 배포 제약을 비교한다.

### 배포 및 보안

- .NET 런타임 의존성 및 배포 방식
- WzLib DLL 라이선스
- WZ 원본 및 추출 이미지의 저작권
- 외부 프로세스 실행 및 파일 경로 검증
- Git 제외 대상

## 5. 설계 원칙

- 기존 아키텍처와 코딩 규칙을 우선 존중한다.
- 기존 기능과 중복되는 시스템을 만들지 않는다.
- 확인된 사실과 가정을 구분한다.
- 불필요한 의존성 및 파일 추가를 피한다.
- 후속 Electron·DB 기능은 설계 범위와 검증 조건을 정한 뒤 구현한다.

## 6. 후속 제안 — Windows 경로 설정과 이미지 DB 백업

**우선순위: 중 · 상태: 대기.** 현재 검증한 것은 C# CLI의 전직 ID 묶음 추출·기존 PNG 재사용·부분 누락 복구와 WSL Electron의 로컬 PNG 표시·직업별 추출 버튼까지다. 아래 Electron 환경설정, Windows 설치본 실행, DB 이미지 백업은 아직 구현되지 않았다. [Electron `REQ003`](../../apps/electron/docs/REQUIREMENTS/REQ003.md)에서 현재 연결 범위를 관리한다.

### 경로와 실행 파일

- Electron 환경설정에서 `Base.wz` 파일 경로, 이미지 저장 루트 디렉터리, 추출기 진입점 경로를 관리한다. 파일·폴더 선택 대화상자로 받은 절대 경로를 저장하고 실행 전 존재 여부와 읽기·쓰기 가능 여부를 확인한다.
- Windows의 `C:\Users\Rc\...`처럼 특정 사용자명을 코드에 넣지 않는다. 앱 설정은 Electron의 사용자 데이터 경로에 저장하고, 이미지 저장 루트는 사용자가 선택한다. 저장 루트를 정하지 않았을 때의 기본 위치는 Windows 사용자별 로컬 데이터 폴더 아래 앱 전용 디렉터리로 제안한다.
- 추출기 진입점은 `maple-skill-extractor.dll` 또는 향후 배포용 실행 파일을 뜻한다. `WzComparerR2.WzLib.dll`과 `WzComparerR2.Common.dll`은 추출기 옆에 함께 배치하므로 별도 파일 선택 항목으로 다루지 않는다. 설치본에서는 추출기를 앱 리소스로 묶은 경로가 기본값이고, 사용자 지정 경로는 개발·문제 해결용으로 둔다.
- Electron Main이 설정한 이미지 저장 루트에 `skills/{version}/{jobID}/{skillID}/{icon|iconMouseOver|iconDisabled}.png`를 붙여 추출·조회·복구에 공통 사용한다. 사용자가 `1.2.419` 출처로 확인한 기존 PNG는 해당 버전 폴더로 이전했다. 이후 출처 미확인 PNG는 자동 이전·표시하지 않는다. 설정 변경 시 기존 파일을 자동 이동하거나 삭제하지 않고 새 루트 적용 여부와 기존 파일 이전 필요성을 명시한다.
- WSL 개발 환경의 `/mnt/<drive>/...` 및 `\\wsl.localhost\...` 변환은 실행 어댑터에만 둔다. Windows 설치본은 선택된 `C:\...`, `D:\...` 같은 네이티브 경로를 그대로 전달한다.

### 이미지 백업과 복구

- 선택한 이미지 저장 루트의 PNG를 추출 결과로 사용한다. PNG 형식 검증 후 DB에 `(데이터 버전, jobID, skillID, 아이콘 종류)`를 식별자로 이미지 바이트, SHA-256 및 추출 출처를 백업하는 방안을 제안한다. 같은 해시의 재실행은 중복 백업을 만들지 않는다.
- 로컬 PNG가 없고 DB 백업이 있으면 선택한 루트에 복구할 수 있게 한다. WZ에서 아이콘 노드가 없는 경우, 추출 실패, 파일 저장 실패, DB 백업 실패를 서로 구분해 기록한다. DB 백업 실패를 추출 완료로 표시하지 않는다.
- 설치된 앱의 `packages/`는 실행 중 생성 파일의 저장 위치로 사용하지 않는다. 현재 DB 스키마에는 스킬 이미지 바이트 모델이 없으므로, 실제 구현 단계에서 `packages/database/db`의 별도 모델과 백업 크기·버전 보존 정책을 설계하고 검증한다.

### 후속 구현 경계

1. Electron 설정 저장·경로 검증과 Windows 네이티브 경로 전달을 구현한다.
2. 추출기와 WzLib 의존 DLL을 설치본 리소스에 포함하고, .NET 런타임 의존 또는 자체 포함 배포 방식을 결정한다.
3. DB 이미지 백업·복구 모델과 재시도 상태를 정의한 뒤 스킬 데이터 UI에 연결한다.
4. Windows 설치본에서 추출, 공통 전직 재사용, 설정 경로 변경, DB 복구를 확인한다.
